R&D Dossier · Phase 2 · August 2026

How the recorder plugs into the agents

Phase 1 settled what to build (a flight recorder for AI coding agents) and on what (Tauri 2.x + Rust). Phase 2 answers the integration question: plugin, MCP, or direct connection? Verdict: a Claude Code plugin carrying HTTP hooks into our local app, backed by transcript tailing. MCP is a query surface, not a capture surface. Plus the day-1 open-source setup.

Claude Code CLI (priority 1): ship a Claude Code plugin. One /plugin install wires hook events over HTTP to the desktop app. It touches no user config files, auto-updates, and can never block or slow the agent: dead endpoint means the hook is silently skipped.

Claude Desktop (priority 2) comes mostly free. Its Code tab runs real Claude Code against the same ~/.claude settings and transcripts, so the same plugin fires there. Only Desktop's plain chat needs a different trick (an MCP logging proxy).

Open source from day 1: yes. AGPL-3.0, contributor agreement, signed releases with SBOMs. The auditor must itself be auditable.

01 · The decision

Five candidate mechanisms, ranked

All five ways of connecting were evaluated against the job: passive, reliable, real-time capture with session attribution, that can never break or slow the agent.

MechanismRoleWhy
Plugin + HTTP hooksPrimaryReal-time push of every tool call (full bash command, file paths, session id, permission mode) straight to our localhost server. Hooks from plugins merge with user hooks, never clobber them. Non-2xx, timeout, or connection refused all mean "continue, don't block". Documented public API, one-command install, auto-updates.
Transcript tailingSecondaryWatch ~/.claude/projects/**/*.jsonl for backfill (sessions before install), tool outputs (stdout/stderr), and tamper evidence: activity in the transcript with no matching hook event means hooks were disabled. Format is undocumented and drifts, so parse defensively and treat as enrichment.
Local spool fileSecondaryA tiny async command hook appends NDJSON to a spool the app drains on launch. Covers the gap when the desktop app isn't running, since HTTP hooks fire once with no retry.
OpenTelemetry receiverFallbackThe app can embed an OTLP endpoint; OTEL_LOG_TOOL_DETAILS=1 exports full commands. But it needs env vars set before launch, truncates inputs, and is easy to unset. Offer it for orgs that already mandate OTel or block hooks.
MCP serverNot for captureMCP tools only fire when the model chooses to call them; there is no "subscribe to all activity" in MCP. Correct uses: a bundled MCP server so the agent/user can query the audit log ("what did you change yesterday?"), and a logging proxy for Claude Desktop chat (below).

02 · Claude Code CLI

The plugin: everything in one installable unit

Claude Code's plugin system lets one package ship hooks, an MCP server, skills, and binaries together, distributed through a marketplace repo: users run /plugin marketplace add ourorg/recorder then /plugin install, and version bumps auto-update in the background. Prior art validates every piece: community projects already ship hook packs as plugins, and the popular hooks-observability template does exactly our POST-to-localhost pattern, just without the clean packaging.

The hook surface has grown to ~31 events. The recorder subscribes to the audit-relevant set:

{
  "hooks": {
    "PreToolUse":  [{ "matcher": "*", "hooks": [{ "type": "http",
      "url": "http://localhost:48620/ingest", "timeout": 5 }] }],
    "PostToolUse": [ ... same ... ],
    "PostToolUseFailure": [ ... ], "PermissionRequest": [ ... ],
    "PermissionDenied": [ ... ], "UserPromptSubmit": [ ... ],
    "SessionStart": [ ... ], "SessionEnd": [ ... ],
    "SubagentStart": [ ... ], "SubagentStop": [ ... ],
    "ConfigChange": [ ... ]   // fires when settings change: a tamper signal
  }
}

Each event delivers session_id, prompt_id, transcript_path, cwd, permission_mode, and for tool events the full tool_input (the complete Bash command string, file paths for edits) plus tool_use_id, which cross-links to both the transcript and OpenTelemetry. That's the entire audit record, pushed in real time, including whether the user was running in bypass-permissions mode.

What can break it, and the answer

Enterprise managed settings can disable hooks (disableAllHooks, allowManagedHooksOnly) or restrict HTTP hook URLs. The flip side is an opportunity: orgs can deploy our hook block via managed-settings.json, which makes the recorder user-tamper-proof, exactly what a team tier sells. Hook payload contracts have had occasional regressions across Claude Code versions, but read-only observer hooks that just serialize stdin are minimally exposed; the breakages historically hit hooks that make allow/deny decisions.

03 · Claude Desktop

Code tab is covered free; chat needs a proxy

Code tab

Runs real Claude Code against the same ~/.claude settings and writes transcripts to the same ~/.claude/projects/. Our plugin's hooks fire there unchanged. Zero extra work.

Cowork / agent mode

Sessions run in an isolated VM but leave tailable local stores under Application Support/Claude/local-agent-mode-sessions/ (macOS) and %AppData%\Claude\ (Windows), including a per-session audit.jsonl. The app watches these paths.

Plain chat

No hooks exist. The only local interception point is MCP: our installer can rewrite claude_desktop_config.json to route each configured MCP server through a logging stdio proxy (an established pattern), capturing every MCP tool call. Built-in non-MCP tools remain invisible locally; that's a platform limit, worth stating honestly in our docs.

Query surface

A one-click .mcpb desktop extension ships our MCP query server, so users can ask Claude Desktop itself "what did my agents do today?" against the local audit database.

04 · Beyond Claude

Every major agent converged on the same hook shape

Codex CLI shipped a hooks system in 2026 that is a near-clone of Claude Code's (same JSON-on-stdin, exit-code semantics). Cursor, Gemini CLI, Copilot CLI, and Windsurf all run their own variants; Cursor's has been proven for exactly our use case at enterprise scale (Elastic logged 13M+ tool-call events across 1,100 machines with one hook script). So the core carries one normalized event schema, and each agent gets a thin adapter combining its native hooks with native log tailing:

Agent-agnostic and always on, regardless of adapter: the package-manager watcher (lockfile diffing plus optional PATH shims for npm/pnpm/pip/uv/cargo), because package installs are under-reported by every agent's own tool events, and packages are the top attack vector from the phase-1 threat research.

App architecture

Ingest server

Rust (axum) HTTP listener on a fixed localhost port receiving hook POSTs from all agents, plus an optional embedded OTLP receiver.

Adapters

Per-agent modules: installer (merge hooks non-destructively, verify on startup since most agents read hook config only at launch), log tailer, format normalizer.

Event store

Normalized events (agent, session_id, ts, kind, payload, source, confidence) in local SQLite. Local-only by default; that privacy stance is the product.

Timeline UI

Tauri webview: per-session drill-down, package feed with threat-feed flagging, danger alerts, daily digest.

05 · Open source, day 1

The auditor must be auditable

Every trust-critical endpoint tool that developers actually adopt is open source: LuLu (GPL), Portmaster (AGPL), Bitwarden (GPL/AGPL), Tailscale's client. A closed-source app that watches everything your AI does would be rejected by exactly its target audience. The recommended setup:

License

AGPL-3.0 + CLA

Free and fully open for every user; anyone turning it into a hosted clone must publish their changes (the Plausible/Portmaster shield). A contributor agreement from the first external PR preserves the right to dual-license a future commercial ee/ team tier (the Cal.com/Bitwarden pattern). MIT is the wrong choice: Plausible got cloned commercially and switched away for this exact reason.

Supply chain

Signed, attested releases

GitHub Actions matrix build via tauri-action; notarized macOS builds + Azure Trusted Signing on Windows; Sigstore artifact attestations (SLSA); cargo auditable so every binary embeds its dependency tree; CycloneDX SBOMs as release assets; OpenSSF Scorecard running on schedule. Document reproducible-build status honestly (Rust/Tauri isn't fully there yet).

Repo + launch

Monorepo, brew tap, Show HN

Layout: apps/desktop, crates/ (recorder core as a reusable library), docs/ (Starlight), packaging/. SECURITY.md with private vulnerability reporting. Launch: Show HN with a "here's what it caught" demo, then r/ClaudeAI; own brew tap + winget manifest from day 1. Never paywall recording fidelity or safety signals; paid is team sync, SSO, and compliance exports only ($8-10/dev/mo territory).

Naming note

"Blackbox" is unusable (blackbox.ai, a 30M-user AI coding product, owns it). "Flight recorder" works as the descriptor but is generic as a brand (JDK Flight Recorder etc.). Before announcing any name: check GitHub org, npm, crates.io, domain, and a USPTO search. Coined names beat descriptive ones for later trademarking.
